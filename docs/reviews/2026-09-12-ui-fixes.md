# UI fixes — 2026-09-12

Implemented the UI round from [SHOW_PREP_TODO.md](../SHOW_PREP_TODO.md), based on `main` at `24e1a27`.

## Changes

- Table, grid and photo-detail modal share `PhotoThumbnailService`. It reads existing JPEG bytes directly, uses actual show/class fields and configured small/large suffixes, and caches successful reads. No Intervention decoding or recompression is needed to display a proof. Missing thumbnails do not disable subsequent rows, and a failed modal load clears any previous photo.
- Proof-search labels and redirects use the class relation, preserving underscore show IDs and class names. Redirect path segments are URL-encoded.
- Filename, path and photo-ID arguments are encoded for JavaScript in rename, import, reveal, copy, selection and modal controls. Flux button attributes use `Js::from` inside a Blade echo: testing showed a bare `@js` directive can survive Flux compilation literally in an attribute.
- The preview-watermark checkbox uses a live model binding and an updated-property hook. Browser reproduction confirmed the former model update plus toggle action inverted the requested value a second time.
- Grid Select all uses an Alpine binding. The previous `:checked="selectAll"` was interpreted as a PHP constant by the Flux compiler and could prevent grid rendering.

The parent also eager-loaded class relations for the photo list to avoid a separate relation query for every thumbnail.
